# changjietu v0.2.19 更新日志

本版聚焦频繁重切期间的 UI 状态竞争：后台重新编码完成时，不能用启动任务时保存的旧状态覆盖用户刚刚修改的切片选择。修复基于源码竞态分析与 JVM 回归测试，尚未取得 Android 真机并发复现证据。

## 新增

- 新增 `ReprocessSelectionPolicy`，明确切片数量不变时保留最新选择、数量变化时维持全选的既有规则，并过滤无效索引。
- 新增三项 JVM 回归测试，覆盖最新选择保留、切片数量变化、非法索引过滤。

## 修复

- 重切结果完成时使用 `MutableStateFlow.update` 原子读取并合并当前选择，而非直接用旧 `EditorState` 快照整体覆盖。
- 重切失败时只更新当前编辑状态中的错误和处理标志，不恢复旧快照。
- 完成与异常路径校验源图片 URI 和 `sourceGeneration`，避免切换图片后旧任务写回过期结果。
- 更新 PROC-03 状态机源码锚点，匹配新提交路径。

## 验证

- PR #31 的提交 `9e921a18`：Android verify and publish Run #43030376770 的 verify 通过，覆盖 Debug 单测、构建、Lint、Release Vital Lint 与有界形式化检查；PR 构建的 publish 步骤按设计跳过。
- Formal state-machine verification Run #43030376705 通过，包含有界 TLC 模型和负对照。
- 首次 CI 曾因源码锚点陈旧及代码修改失败，后续修复并在上述最新提交上通过；不得把早期失败视为成功。
- 三项 JVM 测试通过不等于已经完成受控协程 A/B 任务竞争复现；Android 真机触控、切换图片、并发重切和导出尚未实测。
- 正式签名构建、原证书连续性、APK 大小、远端 SHA-256 将由本次 `[publish]` 流水线验证并自动追加至 GitHub Release，不能提前宣称完成。

## 已知限制

- 尚无覆盖两次重切 A/B 交错、取消期间文件清理和源图片切换的完整确定性调度测试；需继续补齐。
- 切片数量变化时仍按原行为全选，不尝试猜测用户对新切片的选择意图。
- 自动切线仍可能截断图片、图表、表格和文字；超长图预览压缩、跨应用分享排序差异仍待验证。
- 本版未引入 OCR、视觉模型或新型图像裁切算法，也未加入无损 PNG 输出。
