# 2026-11-11 长截图真实反馈：切线穿过图表 / 表格

## 可确认的用户实机证据

用户上传了 4 张 v0.2.12 的「调整切线」截图。可见蓝色切线：
- 穿过费马大定理形式化实验的折线统计图内部；
- 横穿一张多列多行的模型评估表格；
- 位于深色图片上缘附近；
- 在社交帖子内容和卡片之间有时能落在较自然的位置。

**限制**：提供的是编辑器屏幕截图，不是没有叠加 UI 控件的原始长图，因此不能从截图推出可靠的源图 Y 坐标，也不能把它当成“模型正确识别原图”的黄金样本。

## 已证实的代码级原因

v0.2.12 的 `SplitPointDetector.energyAwareRanges` 对任何检测出的块仍使用目标单片高度的硬上限，同时把最小切片推进量限制到 `target * 0.55`。即使发现图片开始前的空白，也可能因早于 55% 而禁止选取；视觉块长度跨越目标值时，回退到最小行能量并允许切入检测禁区。OCR 只定位文字行，更不能作为整图完整性的验收标准。

## v0.2.13 行为修复

- 新增 `VisualSeamPlanner`，只有真正检测出视觉内容区域时才启用；否则回落原有文本 OCR/行能量算法，保持已有契约。
- 区分视觉块范围与 OCR 行范围，不能用 OCR 行间空白推断“整个表格安全”。
- 提前允许自然切点（不再强制 >55% 目标高度）；图表与表格被保护时，可在内存安全限制内扩展到最大 **1.8× 目标高度，且单片不超过 8000px**。
- 如果目标高度允许范围内没有不截断的切点，仍保留完整源图像素覆盖，`uncertainCuts` 应标记强制切点，供手动调整。
- 新增回归：图表中线、长表格、照片边缘、无解超长块、重叠及 50000 像素原图等，保持预览/导出算法完全同一。
- 不加入任何大型新模型，不依赖网络；APK 内置 OCR 部分暂未优化。
- 文案明确说明检测可能漏报以及适当延长切片的取舍。

## 证据分层 / 发布门禁

- 算法单测和 Android CI 通过只能证实已标注视觉禁区的规划结果，不等于已经在用户原始图像上复现。
- 只有具备原始长图 + 安全区标注 + 实际导出像素比对才可声称“这个案例已彻底修复”。
- 发版以原 GitHub Actions 的 Android CI、签名证书连续性、Release APK + SHA-256 远端回读为准。真机回归待原始源图才能完成。
