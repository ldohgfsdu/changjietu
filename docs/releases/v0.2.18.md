# changjietu v0.2.18 更新日志

本版针对缓存清理与导出读取之间已通过 JVM 并发测试复现的竞态窗口进行修复，不改变切片算法或输出格式。

## 新增

- 增加确定性并发回归测试，覆盖清理检查、实际删除与新导出读取租约竞争的顺序。
- 导出源文件已被清理或失效时，返回可处理的错误，而不是继续尝试读取不存在的文件。

## 修复

- 将缓存清理的判断和递归删除置于与导出读取租约、分享保留标记一致的同步边界，防止在检查允许删除之后、实际删除之前插入新的读取租约。
- 相册保存和 ZIP 导出取得文件租约失败时，通过原有结果回调报告错误。
- 修正回归测试的临时目录时间戳，保证测试环境中的保留期判断稳定。

## 验证

- PR #30 的最新提交 db0a2a9d：Android verify and publish Run #42985021528 的 verify 通过，涵盖单元测试、Debug 构建、Lint、Release Vital Lint 与有界验证。
- Formal state-machine verification Run #42985021572 通过，包含 TLC 模型、负对照和状态图生成。
- 本版合并提交 066ea376。正式发布流水线还需对版本递增、原签名证书、远端 APK 回读及 SHA-256 做最终验证；不能以 PR 测试替代正式 APK 验收。
- 未进行 Android 真机实测；组件级竞争复现不等同于已证实的手机端事故。

## 已知限制

- 递归删除期间仍会在 IO 工作线程持有保留机制锁，可能影响同时申请租约的等待时间，尚无真机延迟测量。
- 已分享文件依旧采用既有 24 小时保留策略；不能保证第三方应用在任意更长时间后仍可读取文件。
- 自动切线仍可能截断图片、图表或文字；极长图预览压缩和外部分享应用排序差异尚未解决。
- 不包含新的 OCR 或 ML Kit 依赖；本版不修改切线几何与导出文件格式。
