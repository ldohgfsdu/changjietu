# 长截图样本回归基线（长期保留）

**本文件是测试规范，不是“已通过实机验收”的声明。**

## A. 每次算法改动必须重跑

- `app/src/test/java/com/changjietu/app/image/analysis/ScreenshotSampleRegressionTest.kt`
- `ContentAwareCutTest.kt`、`ContentProtectedRowsTest.kt`、`SplitPointDetectorUnsafeSeamTest.kt`
- `SafeCropMarginsTest.kt`、`SliceGeometryTest.kt`，以及完整 `:app:testDebugUnitTest`
- 现有 `android-release.yml` 对每个 PR 跑全量测试；新增 `screenshot-sample-regression.yml` **每天 UTC 02:41** 单独重跑上述定向回归，可手动触发。该工作流**绝不发版**。
- 失败报告留在 Actions 的 `sample-regression-<run_id>` artifact，供定位具体用例/堆栈。

## B. 当前可重复执行的合成标注样本（不涉及用户截图）

| 代号 | 内容类型 | 容易出现的失败 |
|---|---|---|
| S01 | 连续正文文字行 | 行内切断 |
| S02 | 头像 + 聊天气泡 | 头像切断、气泡上下文丢失 |
| S03 | 密集表格 | 表格行/单元格切断 |
| S04 | 统计图与图例 | 图表和标签被拆开 |
| S05 | 跨屏插图/照片 | 图片区域被切开 |
| S06 | 帖子卡片 + 评论 | 卡片内误切 |
| S07 | 深色背景文字 | 低能量阈值误报空白 |
| S08 | 全程无安全留白的表格 | 不得声称有安全切点，必须显示风险 |
| S09 | 1440 × 50,000 等量级高度的行能量模拟 | 全覆盖、不漏行、单片不超上限 |
| S10 | 头像在左边缘、图例在右边缘 | 自动裁边不可删除左右像素 |
| S11 | 用户选择 120px 重叠 | 必须仅重复配置的像素高度 |

说明：S01–S07 各有 5 个确定性随机扰动种子，总计 35 次算法检查。**这些测试以人工标注的“保护区”和合成行能量作为输入，不会运行真实 ML Kit 视觉检测，所以只证明切点选择和坐标契约，不证明 OCR 能找到头像、表格或图片。** S08 无解样本必须仍可无丢行导出，但标红；不应把测试写成必然找到安全切点。

## C. 真实截图基准库（待原图入库前未通过）

原始图应在有授权的前提下去标识化后存入 Git LFS 或受控测试存储。当前对话中的“调整切线”照片只是编辑器截图，**不是原长图**，无法从中还原精确的像素标注或导出的裁切结果，禁止将其当作 golden image。

建议真实样本 `R01–R20` 至少包括：
- 中文小字正文、英文段落、混排、深色背景；
- 头像/昵称/气泡、连续动态帖、长表格、带水平线表格；
- 折线图、饼图、竖直长照片、图片+文字；
- 低分辨率严重压缩图、透明 PNG、特殊宽高比、50000px 高长图；
- 不同品牌设备选择图片、预览拖切线、保存相册、ZIP 分享、顺序校验。

逐张样本登记：`sample_id`、原图 SHA-256、宽高、许可证或脱敏状态、禁切区 Y 坐标、允许切点窗口、目标单张高度、重叠策略、预期自动裁边、预期最终切片哈希或像素区域摘要。

实际验收需独立核验：
1. 原图所有要求保留的像素都被输出覆盖，无意外留白/隐藏 padding。
2. 切线不穿过标注的文字、头像、表格、图片；若单片最大高度使之不可能，则正确给出风险状态，不把图像分割说成完美。
3. 保存与 ZIP 中相邻图片像素边界、数量、顺序和预览一致；需要无损像素对比时使用 PNG 而非 JPEG 压缩字节。
4. 发布构建内存峰值、端侧 OCR 延迟和 APK 体积单独记录。

## D. 禁止虚报的测试结论

- 仅合成行能量测试通过 → **切点算法基本契约通过**，不得宣称头像、表格检测成功。
- OCR 文本行测试通过 → **已标注/已识别文字行可避让**，不得宣称完整图片块已经识别。
- GitHub CI 全绿 → **静态/单测与构建门禁通过**，不得冒充真机 UI/导出像素已验收。
- 定期回归红灯 → 记录失败用例、可复现种子和原因；修复前不能把变更计为合格发布候选。

后续每次真实 Bug：先留下可复现样本与明确失败断言，再修算法，再跑完整旧样本集合。不得删掉失败样本来获得绿灯。
