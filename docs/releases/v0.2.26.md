# changjietu v0.2.26 更新日志

本版针对用户实机反馈的“自动蓝色切线穿过长表格底部”问题，增加基于图像结构的保守寻缝保护。它改善带连续竖向网格线的表格切分，不代表所有图表都能完整识别。

## 新增

- 在既有 BitmapRegionDecoder 分块采样过程中，增加连续平行竖向边缘检测，识别可能属于同一张表格的源图行区域。
- 自动寻缝避开已识别的表格内部“假空白”；遇到接近目标切片高度的长表格，可适度提前寻找真正的段落分界。
- 生成前预览、正式切片和红色风险切线提示共用同一份源坐标保护标记。
- 新增模拟长表格、稀疏文字、独立竖向边界、超高表格的 JVM 回归测试。

## 修复

- 修正行能量低、但仍位于持续表格边框内部时被错误认为安全切缝的问题。
- 修正末尾切片重平衡可能绕过结构保护区域的行为。
- 精细切线编辑的蓝/红提示改为描述当前位置是否检测到可靠空白，避免误认为拖动操作会使切线变红。
- 保留原采样尺寸、原有只扫描一次的分析缓存，避免额外全图解码；不改压缩、导出、分享和图片文件生命周期。

## 验证

- PR #38 功能提交 16fa2993：Android verify and publish #43352758642 通过，覆盖 JVM 单测、Debug 构建、Lint、Release Vital Lint 和内置状态机检查。
- Formal state-machine verification #43352758489 通过。
- 回归检查确认模拟表格内部的白色单元格不再被当成可靠分隔行；独立竖向引导线不会被误判为多列表格。
- 版本与更新日志合并后的最终代码仍需 CI、正式签名、远端附件哈希回读检查。
- 这属于自动化与合成样本验证，不等于已在用户提供的原始长图上复现并证明完全修复。

## 已知限制

- 对无明显竖向网格线的图表、复杂图片及不规则背景，仍可能无法找到安全分割点，需人工调整。
- 当一个完整图表本身超过配置的单张高度上限时，无法同时保证“严格高度上限”和“图表永不被切断”；风险切线将继续提示不确定性。
- 可能为避开图表而增加切片数；需要实际设备测试导入耗时、切点位置以及切片输出的一致性。
- 本版不引入 OCR、云端模型、PNG 编码、导出顺序修改和额外整图 Bitmap 解码。
