# 端侧内容感知切点 V1 — 验收与发布门禁

状态：**Draft PR 候选，仅本地文字行避让，未完成 Android CI / 实机验证，不能发版。**

## 目标与边界

在旧版水平行能量寻缝基础上，增加 Google ML Kit bundled Chinese OCR 的**文字位置框**辅助。识别文字只用于保护整行 Y 位置，不保存文本、不上传截图，不对图片像素做生成式编辑。表格、图片、卡片的完整结构仍不保证识别，不能声称“所有内容绝不截断”。

## 执行路径

1. 导入图，原有尺寸/质量/能量分析先返回；初始预览走无 OCR 的保守计划。
2. 默认启动按条带 OCR（1500 px，高度重叠 120 px，源位图通过 BitmapRegionDecoder）；上限 64 个条带，超限/失败明确降级。
3. 仅存放文字行的纵向像素保护区，合并相交区域，保留源图 Y 坐标。
4. 完成后统一重算预览切点；正式导出使用同一保护区。手动切点优先，不重置用户调整。
5. 处理中禁止发起切片，避免预览/导出计划不同；用户可选择“跳过识别”立即继续旧版流程。
6. 切点选取首先避开识别文字行，尾段重平衡同样受约束。无可用缝隙时保留像素完整覆盖，显示截断风险而非静默假装安全。
7. 禁用“本机文字识别避让”后不再使用保护区。再次开启时重新扫描，以防旧数据混用。

## 最小验收矩阵

| 类别 | 输入与操作 | 应看到 |
| --- | --- | --- |
| 文字行 | 中文/英文段落长图 | 自动切线不穿过已识别的文字行（若有安全候选） |
| 表格 | 连续无留白表格 | 无法安全时提示风险，不许显示“已全部安全” |
| 图片 | 跨屏连续图表 | 保留全部像素；仍允许人工调整；不能声称图片分割安全 |
| 边距 | 头像靠近左右边缘 | 自动横向裁边不裁掉左右像素 |
| 状态 | 识别中多次调整切片高度 | 预览更新、无重复 OCR 启动；生成按钮保持禁用直到完成或跳过 |
| 跳过 | 识别中点击“跳过识别” | 立即恢复旧切点模式；旧任务不能把结果写回新状态 |
| 输入切换 | 前一张 OCR 过程中载入新图片 | 前一张结果不能覆盖当前预览 |
| 边界 | 手动拖动切线后 OCR 完成 | 手动切点不丢失，源图/裁切内容坐标一致 |
| 极长图 | 1440 × 50000 | 不整图解码；记录扫描耗时、CPU、峰值内存；可跳过 |
| 导出 | 保存相册/ZIP/系统分享 | 和预览切线一致，源图 Y 坐标覆盖完整且按顺序 |
| 主题 | 深色/浅色 | 48dp 手柄，提示可读，状态不只靠颜色 |
| 发布 | 版本递增、签名校验 | 沿用原 workflow；未验收不得宣称正式发布 |

## 主要风险与未完成事项

- 中文 OCR 对很小或严重压缩的英文字符可能漏检，行框保护不是完备的版面检测。
- 逐条带 OCR 会增加 CPU/内存和 APK 体积；必须真机量化，不能把静态编译当作性能验收。
- 某些来源 URI 在扫描时失效会回退旧路径，用户可重新选择图片。
- OCR 结果不应序列化到磁盘，也不能把截图传到任何第三方 API。
- 下一阶段考虑表格边框/图片块分割，并建立原始长图 + 黄金切片的回归样本。
- Google ML Kit 的本机图像处理与一般 SDK 服务通信行为按其官方隐私条款披露。实际 APK 不新增上传截图逻辑。

本文件对应用户 2026-11-10 授权的端侧 OCR 增量，优先级高于 GOAL.md 中旧的 MVP 禁止 OCR 约束。
