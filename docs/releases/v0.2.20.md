# changjietu v0.2.20 更新日志

本版聚焦连续重切时输出目录可能发生碰撞的可靠性风险。此前重切目录使用毫秒时间戳命名，两次请求落在同一毫秒可能指向相同路径。该风险由源码分析与回归测试覆盖；不宣称已在真机上观察到目录碰撞。

## 新增

- 新增 `ReprocessOutputDirectory`，使用 `Files.createTempDirectory` 原子分配独立重切输出目录。
- 新增 JVM 单元测试，检查连续创建的两个输出目录互不相同且实际存在。

## 修复

- 将后台重切使用的 `slices/${System.currentTimeMillis()}` 目录替换为唯一目录，避免同毫秒任务复用同一路径。
- 保留现有切片处理、导出格式、缓存保留与分享行为；未重新引入重型 OCR。
