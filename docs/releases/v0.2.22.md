# changjietu v0.2.22 更新日志

本版修复后台频繁重切期间，缓存清理可能误删另一项仍在写入的切片目录的竞争窗口。该风险由源码时序分析发现，未声称已在真机复现。

## 新增

- 增加重切输出目录活跃写入引用计数，登记与释放均受同步保护。
- 增加三项 JVM 测试：活跃目录与部分文件保护、重复登记释放、CountDownLatch 控制的写入与清理扫描交错。

## 修复

- 后台重切新任务扫描旧缓存时，跳过仍被编码任务占用的目录。
- 目录创建时同步登记活跃状态；重切任务结束时在 finally 中释放登记。
- 沿用已有唯一目录分配和取消后未提交文件清理机制，不修改切线算法、编码格式或分享流程。

## 验证

- PR #34，提交 `0f5922b2`：Android verify and publish #43101591805、#43101581788 与 Formal state-machine verification #43101591618 均成功。
- 三项 JVM 测试由 Android CI 的 `:app:testDebugUnitTest` 执行；并发测试固定目录已登记、写入未结束的窗口。
- 本次测试不等同于完整 ImageSplitter、协程取消、真实删除的端到端压力测试。
- 发布后仍须经原签名连续性、远端附件回读及 SHA-256 校验；未完成真机安装与导出验收。

## 已知限制

- 缓存扫描中的保护检查与实际删除尚未作为单一原子操作验证；仍需更完整的 A/B 任务交错和取消压力测试。
- 自动切线对图片、图表及复杂排版仍可能不准确。
- 无损 PNG、历史恢复尚未完成；未引入重型 OCR 模型。
- 真机安装、分享、导出与重复重切验收未完成。

## APK 大小

- 正式 APK 的实际字节数和 SHA-256 将由发布流水线构建后记录在 Release 页面；此处不预估。
